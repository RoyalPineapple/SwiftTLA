# Verified Coordination Library — Architecture

## Layers

```
@TLAModel struct VerifiedQueueCore
       │
       │  ┌── written by us ──┐
       ├── static var spec: TLASpec       ← TLA+ model (variables, actions, invariants)
       │
       │  ┌── generated by @TLAModel macro ──┐
       ├── enum Key: String, CaseIterable  ← one case per variable
       ├── struct State                    ← typed fields matching variables
       ├── static var runtime: SpecRuntime ← interactive stepping
       └── extension Core: TLAModelType
       
actor VerifiedQueue<Element>               ← hand-written wrapper, uses Core.State + Core.runtime
```

## What the macro generates

### Name injection

The macro injects variable names from `let` bindings automatically:

```swift
let phase  = Var<Int>()           // → Var<Int>("phase")
let queued = Var<TLASetType>()    // → Var<TLASetType>("queued")
let count  = Var<Int>(value: 5)   // → Var<Int>("count", value: 5)
```

No string literal needed — the binding name IS the variable name.

### Generated types

From the spec variables, the macro emits:

```swift
// ── generated ──

extension VerifiedQueueCore {
    enum Key: String, CaseIterable {
        case queued
        case inFlight
        case completed
        case phase
        case nextID
    }

    struct State {
        var queued: Set<Int>
        var inFlight: Set<Int>
        var completed: Set<Int>
        var phase: Int
        var nextID: Int

        init(from dict: [String: TLAValue]) {
            queued    = dict[Key.queued.rawValue]!.intSetValue
            inFlight  = dict[Key.inFlight.rawValue]!.intSetValue
            completed = dict[Key.completed.rawValue]!.intSetValue
            phase     = dict[Key.phase.rawValue]!.intValue
            nextID    = dict[Key.nextID.rawValue]!.intValue
        }

        var asDictionary: [String: TLAValue] {
            var d: [String: TLAValue] = [:]
            d[Key.queued.rawValue]    = .set(queued)
            d[Key.inFlight.rawValue]  = .set(inFlight)
            d[Key.completed.rawValue] = .set(completed)
            d[Key.phase.rawValue]     = .int(phase)
            d[Key.nextID.rawValue]    = .int(nextID)
            return d
        }
    }
}
```

No action method generation.  The wrapper author writes methods that mutate
`State` and can cross-validate with `runtime` if needed.  The macro stays
simple; the type safety comes from `State` and `Key`.

## How the wrapper uses it

```swift
actor VerifiedQueue<Element: Sendable> {
    private var state: VerifiedQueueCore.State
    private var buffer: [Element] = []

    init(capacity: Int) {
        self.state = VerifiedQueueCore.State(
            queued: [], inFlight: [], completed: [], phase: 0, nextID: 1
        )
    }

    func enqueue(_ value: sending Element) async throws {
        // Check precondition against proven state machine:
        guard state.phase == 0, state.queued.count < capacity else { ... }
        state.queued.insert(state.nextID)
        state.nextID += 1
        buffer.append(value)
    }

    // Optional: runtime cross-validation during tests/debug
    #if DEBUG
    func validateState() -> Bool {
        let dict = state.asDictionary
        return VerifiedQueueCore.runtime.initialStates().contains { ... }
    }
    #endif
}
```

## What each layer is for

| Layer | Written by | Purpose |
|-------|-----------|---------|
| `spec` | us | TLA+ model, verified at compile time by @TLAModel |
| `Key` | macro | string-key safety, `CaseIterable` for exhaustiveness |
| `State` | macro | typed state, `init(from:)` / `asDictionary` bridge to runtime |
| `runtime` | macro | interactive stepping, validation during tests |
| Wrapper | us | ergonomic Swift API, real concurrency primitives |

The user sees only the wrapper.
